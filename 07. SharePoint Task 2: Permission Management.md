# 7. SharePoint Task 2: Permission Management

## 📘 Objective

Implement secure and manageable permission structures.

## ⚙️ Step-by-Step Instructions

### Step 1: Design Permission Model

1. Analyze the organizational structure.
2. Identify user roles and responsibilities.
3. Define the required permission levels:

   * View
   * Edit
   * Contribute
   * Full Control
4. Document the permission matrix.
5. Get approval from stakeholders.

> **Tip:** Use role-based access control (RBAC) instead of individual permissions.

### Step 2: Create SharePoint Groups

1. Navigate to **Site Settings** > **People and Groups**.
2. Create groups, for example:

   * `Marketing Team Owners`
   * `Marketing Team Members`
   * `Marketing Team Visitors`
3. Set the default owner.
4. Configure notification settings.
5. Assign permissions to groups.

> **Important:** Always use groups; avoid direct user permissions.

### Step 3: Configure Permission Levels

1. Go to **Permission Levels** in **Site Settings**.
2. Review the standard permission levels:

   * Contribute
   * Read
   * Edit
   * Etc.
3. Create custom permission levels if needed.
4. Define specific capabilities for each level.
5. Document the permission matrix.

> **Important:** Document custom permission levels thoroughly.

### Step 4: Manage List and Library Permissions

1. Select the list or library.
2. Go to **Library Settings** > **Permissions**.
3. Manage inheritance:

   * Inherit
   * Break
4. Assign permissions to groups.
5. Validate permission propagation.
6. Test access as different users.

> **Tip:** Consider breaking inheritance at the list level for sensitive content.

### Step 5: Audit and Review Permissions

1. Use **SharePoint Permission Insights**.
2. Run access reviews quarterly.
3. Identify excessive permissions.
4. Review inactive users.
5. Remove unnecessary access.
6. Document changes.

> **Important:** Regular audits prevent permission creep.

---

## 📋 Best Practices - SharePoint Task 2

8. Use Azure AD groups instead of SharePoint groups when possible.
9. Implement the least privilege principle—grant the minimum necessary permissions.
10. Never grant **Full Control** unless absolutely necessary.
11. Document all permission changes in a change log.
12. Use permission inheritance from the parent site when appropriate.
13. Implement external sharing policies carefully with governance.
14. Review and update permissions when users change roles.
15. Use access reviews to maintain a clean permission structure.
16. Implement conditional access policies for sensitive content.
17. Monitor and audit who has access to sensitive data.
18. Use sensitivity labels to classify and protect content.
19. Implement approval workflows for access requests.
